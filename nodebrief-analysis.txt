2. MOTIVATION & OBJECTIVE
NodeBrief was created to bridge the gap between initial visual architecture ideation and immediate schema/prompt generation for modern software engineering workflows. Traditionally, database modeling and relational schema design involve manually sketching entity topologies on whiteboards or canvas tools, followed by tedious, error-prone manual translation into database DDL, Prisma schemas, TypeScript interfaces, and prompt engineering context for AI coding assistants.

NodeBrief solves this problem by providing an ultra-minimalist, local-first visual canvas workbench. As developers design, drag, and interconnect entity nodes, NodeBrief synchronously compiles the graph topology into production-ready declarative schema formats (Markdown, Prisma, SQL DDL, TypeScript) and hardened LLM context prompts in real time. The platform eliminates context-switching, accelerates system architecture design, and empowers engineers to feed structured context maps directly into AI code generation engines for rapid idea validation.

AI & LLM Integration:
- @google/genai (v2.4.0) for optional Gemini AI prompt generation and assistance

Testing & Code Quality:
- Vitest (v5.0.1) for fast unit test execution

- jsdom (v30.1.1) for DOM emulation during testing
- TypeScript Compiler (`tsc --noEmit`) for strict static type checking

Architectural Patterns:
- Local-First Architecture: In-memory visual graph state synchronized with 500ms debounced browser localStorage persistence (`nodebrief_projects_v1`).
- Compiler AST Pipeline: Decoupled translation engine taking graph nodes and edges and producing structured Markdown, Prisma, SQL DDL, TypeScript Zod targets, and LLM system prompt ASTs.
- Custom Hook Decomposition: Clear separation of state orchestration (`App.tsx`), project storage management (`useProjectManager`), snapshot history management (`useHistoryState`), and keyboard hotkeys (`useCanvasShortcuts`).
- Component Architecture: Clean separation between canvas elements (`SchemaNodeComponent`, `RelationEdgeComponent`), controls (`CanvasWorkbench`), compilation panel (`RightOutputPanel`), and dialog modals (`AddNodeModal`, `AddRelationModal`, `EditRelationModal`, `ExportModal`, `ImportModal`, `ConfirmationModal`).

5. COMPLEX CHALLENGES & ARCHITECTURAL HIGHLIGHTS
Real-Time Multi-Target Schema Compilation Engine:
- Challenge: Generating precise, syntactically correct output across multiple target formats (Markdown, Prisma, SQL DDL, TypeScript, LLM System Prompts) from fluid React Flow node/edge graphs in real time without lag.
- Solution: Engineered a synchronous, deterministic AST compiler pipeline in `src/components/RightOutputPanel.tsx` and compiler utilities. The engine evaluates node attribute arrays, maps Primary and Foreign Key references to target entities, calculates relationship cardinalities, and formats multi-target outputs synchronously whenever node or edge arrays change.

Dynamic Dagre Auto-Layout with Height Calculations & Coordinate Guards:
- Challenge: Laying out entity nodes cleanly when node heights vary dynamically based on the number of fields, avoiding overlap and invalid coordinate values.
- Solution: Built `src/utils/dagreLayout.ts` integrating the Dagre graph library. Dynamically calculates entity card dimensions using field-count formulas ($H = 48 + |fields| \times 28 \text{ px}$) and applies safe separation margins. Added `Number.isFinite()` validation guards across all calculated coordinates to eliminate `NaN` outputs prior to setting state in @xyflow/react.

Interactive Reconnectable Relation Edges:
- Challenge: Allowing users to drag and reconnect existing edge handles on the visual canvas while preserving relation labels, stroke styles, curve paths, and cardinality mappings.
- Solution: Implemented a custom typed React Flow edge component (`RelationEdgeComponent.tsx`) and custom reconnection handlers in `CanvasWorkbench.tsx`. The handler captures handle re-anchoring, validates target node connections, updates the underlying `SchemaEdge` state model, and maintains connection labels and badge positioning.

Debounced Local-First Multi-Project Storage Engine:
- Challenge: Maintaining fast, responsive UI interactions during heavy canvas editing while ensuring local storage remains in sync without causing disk churn or performance degradation.
- Solution: Implemented `useProjectManager` with a 500ms debounced persistence loop. Mutations update local state immediately for zero UI latency, while disk writes to `localStorage` under `nodebrief_projects_v1` are throttled, supporting instant project switching and error recovery.

Focus-Aware Undo/Redo Snapshot History Manager:
- Challenge: Providing seamless undo/redo for graph topology mutations without capturing every text field keystroke or interfering with text input controls inside modals and fields.
- Solution: Created `useHistoryState` for deep-cloned immutable graph snapshots (up to 30 history states) and paired it with `useCanvasShortcuts`. The hotkey listener inspects `document.activeElement` and ignores key combinations when focused on `INPUT`, `TEXTAREA`, or `SELECT` elements.
